# shorty — задание: поднять в k8s

Сокращатель ссылок. Flask + PostgreSQL. Код готов, **всё остальное — твоё**:
Dockerfile, манифесты, Helm-чарт.

## Что умеет приложение

| путь | что делает |
|---|---|
| `GET /` | страница: форма + последние 20 ссылок + **имя пода, который ответил** |
| `POST /api/links` `{"url": "https://..."}` | создать ссылку, вернёт `code` |
| `GET /<code>` | 302-редирект на оригинал, `hits + 1` |
| `GET /healthz` | жив ли процесс. **Базу не проверяет** |
| `GET /readyz` | готов ли к трафику: 200 если база доступна, 503 если нет |
| `GET /metrics` | метрики Prometheus |

Таблицу в базе создаёт само (при первом успешном `/readyz`).

## Конфиг — только через env

| переменная | по умолчанию | секрет? |
|---|---|---|
| `APP_TITLE` | `shorty` | нет |
| `DB_HOST` | `localhost` | нет |
| `DB_PORT` | `5432` | нет |
| `DB_NAME` | `shorty` | нет |
| `DB_USER` | `shorty` | нет |
| `DB_PASSWORD` | *(пусто)* | **да** |

Слушает порт, который ты задашь в gunicorn. Запуск: `gunicorn --bind 0.0.0.0:<порт> app:app`.
На `SIGTERM` пишет в лог `got SIGTERM, shutting down` — по нему видно, дошёл ли сигнал до приложения.

## Грабли, о которых предупреждаю

- **Gunicorn-воркеры.** Каждый воркер — отдельный процесс со своими счётчиками в `/metrics`.
  В k8s масштабируешься репликами, поэтому ставь 1–2 воркера на под, а не 8.
- **Dockerfile.** Вспомни, чем кончилась прошлая неделя: shell vs exec form и кто PID 1.
  Если `got SIGTERM` не появляется в логах и под умирает 30 секунд — вот оно.
- **Postgres.** Посмотри, как официальный образ `postgres` настраивается через env
  и куда он пишет данные. `Deployment` + PVC сработает, но на собесе спросят, почему для БД обычно `StatefulSet`.
- **kind и Ingress.** В kind нет ingress-контроллера из коробки, и порты 80/443 с ноута в ноду не проброшены.
  Для уровня 3, скорее всего, придётся пересоздать кластер с конфигом. Гугли `kind ingress`.
