# Блок 5. Роли

Цель: `web.yml` разложен по ролям. На серверах при этом ничего не меняется, а в проекте появляется структура, которую узнает любой, кто работал с Ansible.

Время: около 50 минут, с заданием «Почини» час.

---

## Шаг 1. Из плейбука в роль

### Теория

`web.yml` уже длинный, и в нём всё в одной куче: задачи, handler, пути к шаблонам. **Роль** — те же самые задачи, разложенные по папкам со стандартными именами. Ansible сам знает, где что искать.

```
roles/
  nginx/
    tasks/main.yml       задачи. С этого файла роль начинается
    handlers/main.yml    handlers
    templates/           шаблоны. Модуль template ищет здесь сам, в src пишется только имя файла
    files/               файлы для copy, так же
    defaults/main.yml    переменные по умолчанию, самый слабый приоритет
    vars/main.yml        переменные роли, сильный приоритет
    meta/main.yml        зависимости от других ролей
```

- в `tasks/main.yml` и `handlers/main.yml` сразу идёт список задач. Строк `hosts:`, `tasks:`, `handlers:` там нет
- обязательна только `tasks/main.yml`, остальные папки по надобности
- в плейбуке остаётся главное: на каких серверах какие роли

```yaml
- name: Database servers
  hosts: db
  become: true
  roles:
    - postgres
```

- скелет роли создаёт `ansible-galaxy role init --init-path roles nginx`. Лишнее (`tests`, `meta`, `README.md`, пустые папки) можно удалить
- роль не знает, на каких серверах она будет работать. Это решает плейбук. Поэтому одну роль подключают в разных плейбуках и проектах, а готовые чужие берут с Ansible Galaxy

### Руками

**1.** Создай скелет роли `nginx` и перенеси в него всё из `web.yml`:
- задачи → `roles/nginx/tasks/main.yml`
- handler → `roles/nginx/handlers/main.yml`
- оба шаблона → `roles/nginx/templates/`. В задачах `src` теперь просто имя файла
- задача с пакетами в этой роли ставит только nginx
- учебные задачи из блока 3 (версия nginx, debug, каталоги в `/opt/lab`) в роль не переноси

**2.** Создай `site.yml`: один play для группы `web` с ролью `nginx`. Файл `web.yml` и папку `templates/` удали.

**3.** Запусти:

```bash
ansible-playbook site.yml
```

Должно быть `changed=0`. Ты переложил все файлы, а на серверах ничего не изменилось: так и проверяют, что при переносе ничего не сломалось. Задачи в выводе теперь называются `nginx : Install nginx`.

## Шаг 2. defaults, vars и вторая роль

### Теория

- `defaults/main.yml` — значения «если тот, кто подключает роль, не задал своё». Их перебивает всё: `group_vars`, `host_vars`, `-e`
- `vars/main.yml` — значения, которые роль считает своими. Они перебивают `group_vars`, `host_vars` и даже `vars:` в play. Из того, что есть в этой программе, сильнее только `-e`
- правило: всё, что может захотеться поменять снаружи, кладут в `defaults`. В `vars` кладут то, что менять не должны: имена пакетов, пути

Цепочка целиком, от слабого к сильному:

```
defaults роли → group_vars/all → group_vars/группа → host_vars → vars в play → vars роли → -e
```

**Теги** помогают запустить часть плейбука:

```yaml
- name: Site config
  ansible.builtin.template:
    src: lab.conf.j2
    dest: /etc/nginx/sites-available/lab.conf
  tags: config
```

`ansible-playbook site.yml --tags config` выполнит только задачи с этим тегом. `--list-tasks` показывает теги у каждой задачи.

### Руками

**4.** Положи в `roles/nginx/defaults/main.yml` строку `site_title: My site`. Закомментируй `site_title` в `group_vars/web.yml` и посмотри, что изменится:

```bash
ansible-playbook site.yml --check --diff
```

На web2 заголовок стал `My site`, а на web1 остался свой из `host_vars`. Раскомментируй обратно.

**5.** Перенеси эту же строку из `defaults/main.yml` в `vars/main.yml` роли и снова запусти `--check --diff`. Теперь `My site` на обоих серверах: `group_vars` и `host_vars` проиграли. Верни строку в `defaults`.

**6.** Сделай вторую роль `common` руками, без `ansible-galaxy`. В ней нужны только `tasks/main.yml` и `defaults/main.yml`:
- роль ставит пакеты из списка `packages`
- по умолчанию в списке htop и curl

Добавь в `site.yml` play для `all` с ролью `common`, он должен идти первым. Список `packages` перенеси из `group_vars/web.yml` в `group_vars/all.yml` и убери из него nginx: его ставит своя роль. Запусти (страница изменится, в списке пакетов больше нет nginx) и проверь, что на lb1 появился htop:

```bash
./lab.sh ssh lb1
which htop
```

**7.** Повесь тег `config` на задачи с конфигом nginx, включая проверку `nginx -t`. Посмотри `--list-tasks`, потом запусти только их через `--tags config`.

## Почини

По времени минут 15. Задание по желанию, но все три ошибки отсюда на практике встречаются постоянно.

Роль `heartbeat` ставит на lb1 systemd-таймер, который раз в N секунд дописывает время в `/var/log/heartbeat.log`:

```bash
ansible-playbook fixme/5-heartbeat.yml
```

В роли `fixme/roles/heartbeat` три ошибки. Они открываются по одной: следующую видно только после починки предыдущей. Третья на ошибку не похожа: плейбук зелёный, но таймер тикает не раз в 10 секунд, как написано в `5-heartbeat.yml`. Сам файл `5-heartbeat.yml` править не нужно.

Проверка:

```bash
./lab.sh ssh lb1
tail -f /var/log/heartbeat.log
```

## Грабли

| что видишь | что это |
|---|---|
| `Could not find or access 'heartbeat.service.j2'` и ниже `Searched in:` | Ansible не нашёл шаблон. В списке видно, в каких папках он искал: сравни с тем, где файл лежит на самом деле |
| `The requested handler '...' was not found` | имя в `notify` не совпало с именем handler-а, буква в букву |
| `The role 'nginxx' was not found in: ...` | опечатка в имени роли, или папка `roles/` лежит не рядом с плейбуком |
| в `group_vars` написано одно, а на сервере другое | та же переменная задана в `vars/main.yml` роли, и она сильнее |
