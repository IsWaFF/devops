# Блок 6. Секреты: vault

Цель: пароль базы лежит в git зашифрованным, на серверы приезжает файлом с правами 600 и не светится в выводе Ansible.

Время: около 30 минут.

---

## Шаг 1. Зашифрованные переменные

### Теория

Пароль открытым текстом в `group_vars` — это пароль в git навсегда: даже если его потом удалить, он останется в истории.

`ansible-vault` шифрует файл целиком (AES-256). В git лежит шифртекст, а Ansible расшифровывает его на лету, если знает пароль от vault.

| команда | что делает |
|---|---|
| `ansible-vault create файл` | создать зашифрованный файл и открыть его в редакторе |
| `ansible-vault edit файл` | править |
| `ansible-vault view файл` | посмотреть |
| `ansible-vault encrypt файл` | зашифровать уже существующий |
| `ansible-vault decrypt файл` | расшифровать обратно |
| `ansible-vault rekey файл` | сменить пароль от vault |

Откуда Ansible берёт пароль от vault:

- `--ask-vault-pass` — спросит при запуске
- `--vault-password-file .vault_pass` — прочитает из файла
- строка `vault_password_file` в `ansible.cfg` — то же, но не надо писать флаг каждый раз

Файл с паролем в git не кладут, он идёт в `.gitignore`. В CI пароль приходит из секретов самого CI.

Принятая раскладка: вместо файла `group_vars/web.yml` делают папку, и Ansible читает из неё все файлы.

```
group_vars/web/
  vars.yml     открытые переменные
  vault.yml    зашифрованные, все с префиксом vault_
```

В `vars.yml` пишут `db_password: "{{ vault_db_password }}"`. Так по проекту можно найти grep-ом, где переменная задана, не расшифровывая файл. В ролях и шаблонах используют `db_password`.

Если секрет один, а файл большой, шифруют одно значение: `ansible-vault encrypt_string`. Результат вставляют прямо в обычный YAML.

### Руками

**1.** Преврати `group_vars/web.yml` в папку: файл должен стать `group_vars/web/vars.yml`.

**2.** Придумай пароль от vault и подготовь файл с ним:
- запиши пароль в `.vault_pass`, права `600`
- добавь `.vault_pass` в `.gitignore`
- раскомментируй строку `vault_password_file` в `ansible.cfg`

**3.** Создай зашифрованный файл:

```bash
ansible-vault create group_vars/web/vault.yml
```

В редакторе напиши одну строку: `vault_db_password:` и любой пароль. Сохрани и посмотри на результат двумя способами: `cat` и `ansible-vault view`.

**4.** В `group_vars/web/vars.yml` добавь `db_user` (любое имя) и `db_password`, который ссылается на `vault_db_password`.

**5.** Сделай роль `app` с двумя задачами:
- каталог `/etc/app`
- файл `/etc/app/app.env` из шаблона, владелец root, права `0600`

Шаблон:

```
DB_USER={{ db_user }}
DB_PASSWORD={{ db_password }}
```

Подключи роль в play для `web` после `nginx`.

**6.** Запусти и проверь:

```bash
ansible web -b -m command -a "cat /etc/app/app.env"
git status
```

На сервере пароль открытый, как и нужен приложению. В git пойдёт только шифртекст, а `.vault_pass` в списке новых файлов нет.

## Шаг 2. Где секрет утекает

### Теория

Vault защищает файл в git. Но расшифрованное значение Ansible может напечатать сам:

- `--diff` показывает содержимое изменившегося файла
- `-v` показывает аргументы и результаты модулей
- упавшая задача печатает свои параметры

А вывод Ansible обычно пишется в лог CI, и читают его многие.

`no_log: true` на задаче прячет её вывод и diff. Цена: если такая задача упадёт, причину тоже не видно. На время отладки `no_log` снимают.

### Руками

**7.** Поменяй пароль через `ansible-vault edit` и запусти с `--diff`:

```bash
ansible-playbook site.yml --diff
```

В терминале оба пароля: старый и новый.

**8.** Добавь `no_log: true` задаче с `app.env`. Поменяй пароль ещё раз и снова запусти с `--diff`: задача `changed`, содержимого нет.

## Грабли

| что видишь | что это |
|---|---|
| `Attempting to decrypt but no vault secrets found` | Ansible не знает пароль от vault: нет ни `--ask-vault-pass`, ни `vault_password_file` |
| `Decryption failed (no vault secrets were found that could decrypt)` | пароль есть, но не тот |
| `ansible-vault create` открыл незнакомый редактор | он берёт редактор из `$EDITOR`: `EDITOR=micro ansible-vault create ...` |
| переменные из `group_vars/web.yml` и из `group_vars/web/` перемешались | остались и файл, и папка. Ansible читает оба, оставь что-то одно |

## На собесе

1. Где хранить пароли в Ansible? Как это устроено?
2. Как пароль от vault попадает в CI?
3. Секрет лежит в vault. Где он всё равно может утечь и что с этим делают?
4. Зачем в `vars.yml` пишут `db_password: "{{ vault_db_password }}"`, а не кладут `db_password` сразу в `vault.yml`?
